# CMA 公告接入与看板完善

## 目标与边界

在现有 React + FastAPI + worker 架构内，将 `cma_publish` 使用的中央气象台公开消息纳入全国极端天气看板。复用并发抓取、失败隔离、来源追溯和中期展望单独展示的思路；部署不依赖相邻项目目录，也不读取其私密配置或发送邮件。

## 实施范围

1. 公告采集、正文解析、入库和 API 独立分层；保留来源 URL、发布时间、抓取时间、涉及省份、天气类型和原文摘录。
2. 公告与展望独立展示；仅标题及发布信息明确的官方颜色预警参与预警地图。禁止用天气强度推测官方预警颜色。
3. 各数据链路独立刷新并暴露状态，部分失败保留已有数据；API 启动不抓外网。预报仅返回请求坐标的数据，缺失时明确展示。
4. 看板增加信息摘要、公告筛选、来源状态、空态和移动端布局，保留省份与地图联动；防止旧请求覆盖新位置。
5. 统一 Python 项目依赖；生产使用静态前端 + Nginx 代理，容器健康检查、持久卷、内网数据库及开发独立编排。

## 失败方式与验收

- 导航或页脚污染正文：只解析正文容器，缺失容器视为来源异常。
- 无时间、旧公告、未来日期、跨月：发布时间与抓取时间分开；无时间不进入正式预警，旧公告不参与当前地图。
- 泛称地区或危险省份别名：省份标签仅匹配明确省名，禁止用“广”推断广西。
- 部分来源超时、全部失败：分别记录来源状态；单个失败不清空其他来源，完全失败不生成模拟公告。
- 重复抓取：依据来源与内容生成稳定标识，幂等更新；新增表不重写现有表结构。
- 位置切换：不能把北京预报展示成四川预报；请求竞态只保留最新响应。
- 验证：解析/持久化/失败隔离的针对性测试、TypeScript 构建、Compose 配置检查；最终运行 API 到浏览器的验收并保存报告和截图。

## 当前环境限制

首次检查时 Docker daemon 未运行；随后用户启动 Docker，已转为真实容器与真实来源验收。
